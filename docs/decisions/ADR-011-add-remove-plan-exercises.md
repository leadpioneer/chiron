# ADR-011 — Добавление и удаление упражнений в схеме

- **Статус:** принято; реализовано и задеплоено 27.10.2026 (`e7d607f`)
- **Дата:** 27.10.2026
- **Владелец:** автор проекта
- **Связанные документы:**
  [`ADR-008`](ADR-008-user-control-and-corrections.md),
  [`ADR-010`](ADR-010-library-exercise-replacement.md)

## Контекст

Замена упражнения уже работает, но нельзя добавить новое подсобное упражнение
или убрать его из схемы на будущие дни. Нужны обе операции, с сохранением
плана, аудитом и без потери уже записанных подходов.

## Решения

### 1. Добавление упражнения

- В тренировке есть кнопка **«＋ Добавить упражнение»**.
- Пользователь выбирает блок (например, «Задняя цепь», «Жим») и ищет
  упражнение в полной базе.
- Создаётся новая версия плана. В неё добавляется назначение:
  - роль `ACCESSORY`;
  - выбранный вариант из базы (при необходимости создаётся `lib_<id>`);
  - 2 подхода, 8–12 повторений, целевой RIR 2;
  - нагрузка `null` — калибровка на первой тренировке;
  - `sessionKey` текущего дня, порядок — после последнего упражнения блока.
- Схема действует в текущем цикле: все `PLANNED`/`IN_PROGRESS` сессии
  переходят на новую версию, поэтому будущие дни того же типа получают
  упражнение. Другие типы дней не меняются.
- Уже записанные подходы, пропуски и незавершённые рекомендации переносятся
  на новые prescription id.

### 2. Удаление упражнения

- Кнопка **«удалить из плана»** доступна для `ACCESSORY`/`AESTHETIC`.
- Основное упражнение удалить нельзя — только заменить.
- Удаление создаёт новую версию плана без этого назначения и действует на
  будущие дни того же типа.
- Если по упражнению уже есть подходы в текущей тренировке, удаление
  блокируется.
- Ссылки `supportsPrimaryId` на удалённое упражнение обнуляются.
- Завершённые тренировки остаются на старых версиях плана.

### 3. Аудит и решения

- Добавление: `MANUAL_EXERCISE_ADD`, `EXERCISE_ADDED`,
  `PLAN_VERSION_CREATED`.
- Удаление: `MANUAL_EXERCISE_REMOVE`, `EXERCISE_REMOVED`,
  `PLAN_VERSION_CREATED`.
- В `decisions` пишется причина `EXERCISE_ADDED` / `EXERCISE_REMOVED`.
- Создание варианта из базы пишет `LIBRARY_EXERCISE_ADDED`.

### 4. Интерфейс

- Добавление — в шапке тренировки; модалка: блок + поиск по базе.
- Удаление — в заголовке подсобного/эстетического упражнения.
- «Убрать» (скрыть в этой тренировке) остаётся отдельной операцией и не
  меняет план.

## Границы

- Добавляется только подсобное упражнение; новые основные — через замену.
- Параметры нового упражнения фиксированы (2×8–12, RIR 2); ручной ввод
  подходов/повторений при добавлении не входит.
- Схема сохраняется в текущем цикле. Следующий цикл по-прежнему строится из
  шаблона; перенос в шаблон — отдельная задача.
- Новых миграций нет: используются версии плана и существующие таблицы.

## Последствия

- Новые API: `POST /api/sessions/[id]/exercises`,
  `POST /api/sessions/[id]/exercises/[prescriptionId]/remove`.
- Новые E2E: добавление, удаление, перенос подходов, UI.
