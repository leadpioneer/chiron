# ADR-004 — Некоммерческий статус и границы обработки данных

- **Статус:** принято
- **Дата:** 25.10.2026
- **Владелец:** автор проекта
- **Связанные документы:** [`v1-decisions`](v1-decisions.md),
  [`ADR-003`](ADR-003-alpha-security-and-operations.md),
  [`P1-agent-brief`](../tasks/P1-agent-brief.md)

## Контекст

Владелец зафиксировал, что Chiron — некоммерческий проект и что сбор и
обработка персональных данных не являются его целью. При этом текущий
V1-контур аутентифицирует пользователя по email или Telegram, хранит профиль,
тренировки и wellness, а также передаёт текст в LLM-парсер. Эти сведения
относятся к персональным данным. Нужно отделить намерение продукта от
фактического состава данных, чтобы не записать в документы неверное
юридическое утверждение.

## Решения

### 1. Некоммерческий статус

- Chiron не продаёт доступ, подписки и платные функции.
- В продукте нет рекламы, партнёрских программ, коммерческой аналитики,
  трекеров и продажи данных.
- Личный контур работает по приглашению, без публичной регистрации и без
  обещания коммерческого сервиса.
- Некоммерческий статус не отменяет требования законодательства о
  персональных данных. Юридическая квалификация остаётся отдельной задачей.

### 2. Цель обработки данных

- Данные существуют только для работы дневника: вход, профиль, план, факт
  подходов, wellness, объяснение рекомендаций и экспорт/удаление.
- Нет маркетинговых рассылок, профилирования, скоринга, рекламы и передачи
  данных третьим лицам, кроме технических подрядчиков, без которых не
  работают вход и LLM-парсинг.
- Минимизация: не запрашивать поле, без которого сценарий работает.
- Сырой текст для LLM минимизируется и хранится ограниченное время по
  `v1-decisions`; LLM не пишет план и не пишет в БД.
- Экспорт JSON и удаление аккаунта остаются доступными.

### 3. Что нельзя утверждать

В документах для пользователей, README и публичных текстах нельзя писать
«персональные данные не собираются» или «персональные данные не
обрабатываются», пока серверный контур хранит email/Telegram id, профиль,
тренировки, wellness и текст для LLM. Корректные формулировки:

- «Chiron — некоммерческий проект без рекламы, аналитики и продажи данных».
- «Данные обрабатываются минимально и только для работы дневника».
- «Коммерческого использования данных нет».
- «Перед публичным запуском нужна юридическая проверка».

### 4. Буквальный zero-PD

Если владелец требует, чтобы персональные данные не обрабатывались вообще,
проект должен перейти на другой контур:

- локальное хранение на устройстве пользователя без серверной БД;
- без email, Telegram и серверных аккаунтов;
- без LLM-провайдера и без отправки текста на сервер;
- без серверных бэкапов и удалённого экспорта;
- без нескольких устройств и синхронизации.

Это отдельный продуктовый срез, а не настройка текущего V1. До его
реализации текущий контур считается обработкой персональных данных в
минимальном объёме.

## Последствия

- P1-B не включает публичную регистрацию и коммерческое использование.
- Юридические документы и согласие на LLM нужны только при расширении до 3–5
  тестеров; для личного режима действует дополнение ниже.
- Если принимается zero-PD, P1-B пересобирается: удаление серверных данных,
  отказ от аккаунтов и LLM, локальный дневник, новая модель экспорта и
  резервных копий.
- Маркетинговые формулировки «мы не собираем ПД» запрещены без смены
  архитектуры и юридической проверки.

## Дополнение от 25.10.2026

Владелец зафиксировал личный режим обработки данных и TMA-only в
[`ADR-007`](ADR-007-tma-only-and-personal-data-scope.md):

- Для использования автором и его близким человеком (партнёршей) применяется
  исключение ч. 2 ст. 1 152-ФЗ; уведомление Роскомнадзора не требуется, пока
  обработка остаётся личной, некоммерческой и без передачи третьим лицам.
- При расширении до 3–5 приглашённых тестеров, публичном доступе или
  монетизации прежний вывод сохраняется: нужны юридические документы и
  отдельная проверка.
- В LLM уходит только обезличенный текст без `userId`, email, Telegram id и
  displayName. Активный провайдер — routerai; Gemini для alpha выключен, чтобы
  не создавать трансграничную передачу.
- Это не отменяет минимизацию, экспорт, удаление и сроки хранения.

## Альтернативы

1. **Заявить zero-PD без изменения архитектуры.** Отклонено: это неверно
   фактически и создаёт риск для владельца и пользователей.
2. **Некоммерческий серверный дневник с минимальными данными.** Принято:
   соответствует текущему V1 и alpha-плану.
3. **Локальный zero-PD дневник.** Отложено: требует отдельного решения и
   переписывания хранения, входа и LLM-контура.
