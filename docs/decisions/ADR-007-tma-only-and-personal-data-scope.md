# ADR-007 — TMA-only alpha и личный режим обработки данных

- **Статус:** принято
- **Дата:** 25.10.2026
- **Владелец:** автор проекта
- **Связанные документы:** [`ADR-003`](ADR-003-alpha-security-and-operations.md),
  [`ADR-004`](ADR-004-non-commercial-and-data-scope.md),
  [`P1-agent-brief`](../tasks/P1-agent-brief.md),
  [`next-sessions`](../tasks/next-sessions.md)

## Контекст

P1-A закрыт и развёрнут на staging. Владелец зафиксировал три решения.

1. Chiron существует только в формате Telegram Mini App. Отдельный Web-вход,
   Login Widget и связка Telegram с существующим Web-аккаунтом не нужны;
   связка откладывается на неопределённый срок.
2. По 152-ФЗ владелец приводит юридическую позицию: обработка персональных
   данных физическим лицом исключительно для личных и семейных нужд не
   подпадает под действие закона (ч. 2 ст. 1), если при этом не нарушаются
   права субъектов данных. Для личного фитнес-дневника уведомление
   Роскомнадзора не требуется, пока обработка остаётся личной.
3. Круг зафиксирован: автор и его близкий человек (партнёрша). Приглашённые
   тестеры в текущий этап не входят; 3–5 тестеров — возможное расширение
   после отдельного решения.

Эти решения меняют состав P1-B и юридический гейт alpha. Их нужно
зафиксировать отдельно, чтобы не менять задним числом `ADR-003` и `ADR-004`.

## Решения

### 1. TMA-only

- Поддерживаемый путь входа в alpha — Telegram Mini App (`initData`).
- BotFather `/setdomain` уже выполнен владельцем. Login Widget технически
  настроен, но не является alpha-путём; email magic link как пользовательский
  путь и связка Telegram с Web-аккаунтом в alpha-гейт не входят.
- Связка Telegram/Web отложена на неопределённый срок. Миграции, таблицы
  кодов, bot-команды и UI для неё не создаются.
- Email и magic link остаются в коде как техническая возможность для
  разработки и владельца, но не являются alpha-путём и не входят в личный
  контур.
- Проверка TMA на реальных iOS Safari и Android Chrome остаётся в P1-B.

### 2. Личный режим персональных данных

- Для использования автором и его близким человеком (партнёршей) владелец
  применяет исключение ч. 2 ст. 1 152-ФЗ. Уведомление Роскомнадзора не
  требуется, пока обработка остаётся личной и семейной, некоммерческой, без
  публичного доступа и без передачи данных третьим лицам.
- Это не zero-PD. Идентификатор входа, профиль, тренировки, wellness и текст
  для LLM остаются персональными данными. Минимизация, экспорт, удаление и
  сроки хранения сохраняются.
- В публичных текстах нельзя писать «персональные данные не обрабатываются»
  или «закон на нашей стороне». Корректная формулировка: «личный
  некоммерческий дневник; данные минимизированы и не используются
  коммерчески».

### 3. Границы личного режима

Личный режим перестаёт применяться, если:

- круг пользователей расширяется за пределы автора и близкого человека,
  включая приглашённых тестеров;
- появляется публичная регистрация, монетизация, реклама или служебное
  использование;
- данные передаются третьим лицам, включая случаи, когда во внешний сервис
  попадает идентификатор или иная персональная информация.

В этих случаях нужен полный режим 152-ФЗ: правовые основания, уведомление
Роскомнадзора (если применимо), ToS, политика ПД, согласие на LLM и проверка
сроков хранения.

В LLM не передаётся идентификатор. В запрос уходят только system prompt и
текст тренировки; `userId`, email, Telegram id и displayName остаются на
сервере. `userId` используется только для бюджета и локальной записи
`llm_calls` (`apps/web/src/lib/llm.ts:311`,
`packages/core/src/llm-client.ts:52`). Поэтому для LLM данные обезличены.

Активный провайдер alpha — routerai (`ADR-005`); Gemini-код остаётся в
репозитории выключенным и для alpha не включается, в том числе чтобы не
создавать трансграничную передачу. Наличие `GEMINI_API_KEY` само по себе
Gemini не активирует: нужен явный `LLM_PROVIDER=gemini`. Включение Gemini —
отдельное решение.
Telegram как платформа TMA участвует в доставке; email-провайдер и S3
используются только для своих функций. По позиции владельца обезличенный
текст без идентификаторов не создаёт передачи персональных данных в LLM.

### 4. Что меняется в P1-B

- Login Widget и связка Telegram/Web убираются из P1-B; `/setdomain` уже
  выполнен и остаётся настройкой бота.
- Остаётся проверка TMA на реальных устройствах. Внешние алерты не нужны;
  журнал инцидентов ведётся по необходимости. Alpha-метрики для личного
  контура не обязательны.
- Alpha — личный контур: автор и его близкий человек. Полный юридический
  пакет для 3–5 тестеров не требуется; уведомление партнёрше передано словами.
- Новых миграций и изменений кода решение не требует.

## Последствия

- P1-B сокращается: связка Telegram/Web не блокирует допуск.
- `/setdomain` выполнен; Login Widget не числится alpha-путём и техническим
  долгом P1-B.
- Круг зафиксирован: автор и его близкий человек. 3–5 тестеров — будущее
  расширение, которое потребует полного юридического пакета.
- README, `P1-agent-brief` и `next-sessions` должны ссылаться на этот ADR.

## Разрешения и настройки (25.10.2026)

- Владелец разрешил commit/push и деплой с рабочей машины.
- На staging `TELEGRAM_ALLOWLIST` содержит 2 записи (автор и партнёрша);
  `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и
  `TELEGRAM_WEBHOOK_SECRET` заданы.
- `LLM_PROVIDER=openai`, `LLM_BASE_URL=https://routerai.ru/api/v1`,
  `LLM_MODEL=~deepseek/deepseek-v4-flash-latest`, `LLM_API_KEY` задан,
  `GEMINI_API_KEY` пуст.
- Внешние алерты не нужны.
- Уведомление партнёрше об обработке данных и LLM передано словами; отдельный
  экран или текст не требуется.
- LLM включена для обоих аккаунтов.
- Деплой `61e84e6` выполнен 25.10.2026; `/api/health` отвечает `ok`, БД `up`,
  LLM `openai`. TMA проверена на iPhone 25.10.2026; Android не проверен.

## Альтернативы

1. **TMA-only + личный режим.** Принято: автор и его близкий человек.
2. **TMA-only + закрытая alpha на 3–5 тестеров.** Отложено: требует
   юридического пакета и отдельного решения.
3. **Web-вход и связка Telegram/Web.** Отложено на неопределённый срок.
4. **Gemini вместо routerai.** Отклонено для alpha: трансграничная передача;
   включение требует отдельного решения.
