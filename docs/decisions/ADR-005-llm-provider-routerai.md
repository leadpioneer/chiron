# ADR-005 — LLM-провайдер routerai для alpha

- **Статус:** принято
- **Дата:** 25.10.2026
- **Владелец:** автор проекта
- **Связанные документы:** [`v1-decisions`](v1-decisions.md),
  [`ADR-003`](ADR-003-alpha-security-and-operations.md)

## Контекст

До alpha нужен живой LLM-парсер. Владелец выбрал OpenAI-совместимый шлюз
routerai, выдал ключ с ограничением по IP сервера и закрепил алиас модели.
Gemini-код остаётся в репозитории как альтернативный провайдер, но активным
для alpha не является.

## Решения

### 1. Провайдер и модель

- Активный провайдер: `openai` (OpenAI-совместимый `/chat/completions`).
- Base URL: `https://routerai.ru/api/v1`.
- Модель: `~deepseek/deepseek-v4-flash-latest` (алиас передаётся как есть).
- Запрос: `temperature=0`, `max_tokens=800`, JSON mode
  (`response_format={"type":"json_object"}`) с возможностью отключить через
  `LLM_JSON_MODE=0`; `reasoning_effort=none` через `LLM_REASONING_EFFORT`,
  чтобы модель не тратила output-токены на reasoning.
- Стоимость берётся из `usage.cost` ответа провайдера, если поле есть; иначе
  оценивается по `LLM_INPUT_USD_PER_1M` / `LLM_OUTPUT_USD_PER_1M`.
- Точный provider label в `llm_calls` — `routerai`; модель сохраняется
  строкой алиаса. Промпт, схема и правила остаются версиями `parse-v1`,
  `1.0`, `1.0.0`.

### 2. Ключи и сеть

- Ключ хранится только в серверном `.env` с правами `640`, не в git и не в
  логах.
- Ключ ограничен IP staging-сервера; локальные вызовы с другой сети могут
  получать `403` и не считаются дефектом приложения.
- При компрометации владелец ротирует ключ самостоятельно; агент не хранит
  резервные копии ключа и не напоминает о ротации.

### 3. Валидация и fallback

- Неизменны: Zod-схема ответа, проверка чисел по исходному тексту, запрет
  ID/ролей/связей от модели, scope-проверка, safety-правила.
- При ошибке провайдера, невалидном JSON, schema mismatch или превышении
  бюджета используется детерминированный парсер; факт и причина пишутся в
  `llm_calls`.
- Автоматического переключения на другого LLM-провайдера нет: это сломало бы
  воспроизводимость. Переключение — только через `LLM_PROVIDER`.

### 4. Бюджет

- Действуют `LLM_DAILY_BUDGET_USD`, `LLM_MONTHLY_BUDGET_USD` и
  `LLM_GLOBAL_MONTHLY_BUDGET_USD`.
- Ставки стоимости задаются `LLM_INPUT_USD_PER_1M` и
  `LLM_OUTPUT_USD_PER_1M`; при изменении тарифа владелец обновляет их.
- `LLM_ENABLED=0` — kill switch, локальный парсер продолжает работать.

### 5. Eval

- `npm run test:llm-eval` работает локально на 50 golden-кейсах.
- `LLM_EVAL_LIVE=1` с ключом провайдера запускает живой прогон и считает
  те же метрики; гейт: red 100%, yellow ≥95%, numeric ≥98%, invalid JSON
  ≤0,5%, scope 100%.

## Последствия

- Смена модели или base URL — релизное решение, фиксируется новым ADR или
  обновлением этого.
- При недоступности routerai качество парсинга падает до локального, но
  дневник и рекомендации продолжают работать.
- IP-ограничение ключа означает, что staging и локальная машина разработчика
  не могут использовать один и тот же ключ.
